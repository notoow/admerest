# admerest 파일럿 운영비 제안

확인 기준: 2026-10-02. 작성: notoow. 아래 금액은 견적이나 결제 승인이 아닌, 공식 공개 요금에 근거한 예산 시나리오입니다. 실제 의료진 실적·유입·수익은 아직 측정하지 않았습니다.

## 제안할 한 문장

“수술 경험을 3D로 보여주는 데서 끝내지 않고, 기록을 접수하고 근거를 확인해 공유하는 서비스를 운영하려 합니다. 한 달 파일럿에서 실제 등록·인증 처리 흐름을 확인하고, 그 결과로 지속 운영 여부를 판단하겠습니다.”

## 백엔드가 필요한 이유

현재 GitHub Pages의 3D 체험은 방문자의 브라우저에서 작동합니다. 여러 사람이 동일한 공개 기록을 보고, 로그인한 사람이 자신의 기록을 수정하며, 운영자가 비공개 서류를 심사하려면 공통 저장소와 계정·권한 관리가 필요합니다.

구현한 구분: 비공개 작성 → 접수 → 보완/승인/반려 → 공개 스냅샷. 미인증은 랭킹에만, 자격·객관적 기록 인증 완료는 공개 탑과 배지까지. 공개된 수치를 수정해도 새 심사가 끝나기 전에는 기존 인증 수치가 유지됩니다.

두 번째 열의 $45는 admerest만의 비용이 아니라 같은 조직의 3개 프로젝트를 한 달 내내 Micro로 운영한다는 가정의 **조직 총액**입니다. 실제 계정별 비용은 프로젝트 생성 전에 조회해 확인해야 합니다. 중지된 프로젝트, 사양 변경, 사용량 초과, 추가 옵션에 따라 달라집니다.

별도 조직의 1개 프로젝트로 3개월 파일럿이면 기본 백엔드 예산은 **$75**라는 계산입니다. 세금·환율·카드 수수료·도메인·메일·운영자 인건비·초과 사용료는 포함하지 않았습니다. 병원 부담액과 기존 개인 프로젝트 비용은 분리하는 편이 명확합니다.

공식 요금: [Supabase Pricing](https://supabase.com/pricing), [조직 단위 과금 설명](https://supabase.com/docs/guides/platform/billing-on-supabase).

로그인 메일은 별도 SMTP 설정이 필요합니다. Supabase 기본 메일은 팀에 등록된 주소 위주로 제한되며 정식 운영에 적합하지 않습니다. [공식 SMTP 안내](https://supabase.com/docs/guides/auth/auth-smtp). 메일 공급자는 아직 선정하지 않았습니다. 예를 들어 [Resend 요금표](https://resend.com/pricing)는 무료 플랜과 일 100회 제한을 안내합니다. 발신 도메인 검증·월 한도·예상 발송량 확인 후 도입합니다.

## 3분 시연

1. [신청자 시연](https://notoow.github.io/admerest/account.html?demo=1) → 첫 기록 → 예시 채우기 → 저장.
2. 가상 자료 2종 준비 → 심사 요청. 3,100건과 2,900장의 차이를 설명합니다.
3. 심사자 화면 → 보완 요청 또는 두 항목 확인 후 인증 승인.
4. 신청자 화면 → 내 공개 탑 보기. 에펠탑과 비교하고 눈높이로 둘러봅니다.

시연은 같은 브라우저 탭 안의 가상 자료로 작동합니다. 실제 회원·자료를 접수하거나 인증하는 것이 아닙니다. [공개 서비스 소개](https://notoow.github.io/admerest/brief.html)는 시연 자리에서 바로 열 수 있습니다.

## 승인받을 운영 범위

- 백엔드 조직 소유자와 비용 부담자, 서비스·소스의 권리와 담당자.
- 전문의 자격 및 객관적 집계 자료의 확인 기준, 지정 심사자, 보완 처리 기준.
- 개인정보 고지, 자료 보관·삭제 기간, 담당자 접근 범위 확정 후 실제 첨부 접수 개설.
- 환자별 정보는 접수하지 않고 식별 정보를 가린 집계 자료만 받는 운영 원칙.

## 파일럿에서 볼 지표

실제 접수 건수, 인증 완료 수, 보완 요청 비율과 이유, 심사 소요 시간. 방문 분석과 광고 성과는 아직 수집하지 않으므로 성과 자료로 제시하지 않습니다. 광고주 모집 행은 준비돼 있지만 유료 광고 판매·매출은 발생하지 않았습니다.
